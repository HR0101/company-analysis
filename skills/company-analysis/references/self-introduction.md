# 会話履歴から作る約1分の自己紹介

応募・選考対策のフル版と面接直前版では、志望動機と別に、そのまま話せる約1分の自己紹介原稿を作る。企業研究・内定比較だけの依頼には追加しない。ユーザーが不要と指定した場合は省略する。

## 使う情報

1. 現在の会話で本人が伝えた所属・職歴・研究・学習・プロジェクト・実績・強みを拾う。最新の訂正を優先する。
2. 提供済みの履歴書・職務経歴書・プロフィール等で不足を補う。別の会話は、実行環境で実際に参照可能かつ利用対象として指定されている場合だけ使う。すべての過去チャットを自動で閲覧できるとは説明しない。
3. 本人の経験と、企業のIR情報・求人要件・他人の話・例文・過去にAIが作った未確認の自己PRを分ける。質問した技術や関心のある業界を、経験・資格・実績として扱わない。
4. 経歴の中から希望職種と関連する1〜2件を選ぶ。所属、経験、数値実績に矛盾があれば、その部分だけ確認する。

経歴が十分なら再入力させずに作成する。情報が足りない場合は、利用可能な質問UIの自由入力で「現在の所属・仕事または研究、代表的な経験や成果、強み」をまとめて1問だけ確認する。回答がない場合は残りの企業分析を進め、自己紹介は必要な確認事項を示した下書きに留める。氏名、学歴、会社名、役職、年数、数値、資格、第一志望度を補って完成品に見せない。

## 原稿の構成

- 挨拶・氏名・現在の所属：10秒程度。氏名が不明なら名前を含めずに話せる表現にする。
- 主な経験・取り組み：25秒程度。本人が何を担当し、どう行動したかを簡潔に述べる。
- 確認済みの成果と強み：15秒程度。数値が不明なら数値を入れない。
- 希望職種との接点・結び：10秒程度。志望動機の全文を繰り返さない。

日本語250〜350字を初稿の目安とし、自然な敬体の一続きの話し言葉にする。字数だけで正確な所要時間を保証しない。実際に音読する前提で冗長な列挙を減らす。情報が少ない場合は、字数を満たすために事実や熱意を足さない。

完成原稿の後に「使用した経歴の根拠（会話での記述または資料名）」と、残っていれば要確認事項を短く添える。根拠注記は読み上げ原稿に含めない。

## レポートへの反映

会話上で完成レポートを作る場合は、原稿を自己紹介セクションへ直接記載する。`report_generator.py` を使う場合は、作成した読み上げ原稿だけを一時ディレクトリのUTF-8ファイルに保存し、`--self-introduction-file` へ渡す。根拠と確認事項は別にレポートへ追記する。経歴や原稿をスキルのソース・公開用リポジトリへ保存しない。

スクリプト単体は会話履歴を取得しない。ファイル未指定なら記入欄を生成するため、スキルが上記手順で原稿を補完してから納品する。
