# 入力UI：ホストの質問ツールを使う（Codex / Claude 両対応）

このスキルは、実行環境が提供する質問UI（Codex の `request_user_input_async` / `request_user_input`、または Claude Code の `AskUserQuestion`）を呼び出して条件を集める。独自のウィンドウやWebフォーム、MCPサーバーを起動する機能ではない。表示形式はホストが決める。

## 起動とツール選択

「入力UIで始めたい」「項目を選んで分析したい」、または対象企業・分析目的が未指定のままスキルを起動した場合は、以下の入力フローを開始する。企業研究・選考対策の既存の依頼から分かる条件を先に `state` へ入れ、同じ内容を再質問しない。

1. 現在のツール一覧とモード制約を確認する。
   - **Codex で `request_user_input_async` が利用可能な場合**: `--ui async` を使う。
   - **Codex で `request_user_input` が利用可能な場合**: `--ui standard` を使う。
   - **Claude Code で `AskUserQuestion` が利用可能な場合**: `--ui standard` を使う。返された `arguments.questions` の各要素（`header`, `question`, `options`）に `multiSelect: false` を添えて `AskUserQuestion` を呼び出す。
   - 名前空間の接頭辞は実環境のものを使う。
2. いずれも利用できなければ `--ui text` に切り替える。UIを出すためにモードを変更したり、アプリを操作・再設定したりしない。スキルの文章だけでツールを追加することはできない。
3. `scripts/input_ui.py` をこのスキルのディレクトリ基準で実行する。スクリプトのJSON出力そのものは入力画面ではない。返された `arguments` を使って、実際の質問ツールを呼び出す。

```bash
# 条件未指定で起動。企業名と目的を尋ねるための引数を生成する（Codex async 例）
python3 scripts/input_ui.py --ui async

# Claude Code (AskUserQuestion) や選択肢数制限ありUIの場合
python3 scripts/input_ui.py --ui standard

# 会話で判明している条件を引き継ぎ、残りの項目だけを尋ねる
python3 scripts/input_ui.py --ui async \
  --state '{"company":"対象企業","purpose":"selection","role":"software-ai-engineer","stage":"second-interview"}'
```

## 入力項目と順序

| 項目 | 入力方法 | 対象 |
| :--- | :--- | :--- |
| 対象企業・業界 | 自由入力 | 未指定の場合 |
| 分析目的 | 企業研究 / 応募・面接対策 / 内定比較 | 明示的なUI起動で未指定の場合 |
| 業界 | 8業界または「おまかせ・未定」 | 条件設定を行う場合 |
| 希望職種 | 6職種または「おまかせ・未定」 | 選考対策・内定比較 |
| 選考フェーズ | 6フェーズまたは「おまかせ・未定」 | 選考対策。内定比較では設定済み |
| 応募区分 | 新卒 / 中途 / 第二新卒 / おまかせ・未定 | 選考対策・内定比較 |
| 企業タイプ | 4タイプまたは「おまかせ・未定」 | 条件設定を行う場合 |
| 出力形式 | フルレポート / 面接直前チートシート | 選考対策。企業研究・内定比較では自動設定 |
| 逆質問の件数（応募者 → 企業） | 標準10問 / 3問 / 5問 / 10問 / 不要（0問）、自由入力も可 | 選考対策。出力形式を選択した後 |
| 想定質問の件数（企業 → 応募者） | 標準100問 / 10問 / 50問 / 100問 / 不要（0問）、自由入力も可 | 選考対策。逆質問とは別に指定 |
| 比較企業 | 自由入力。「おまかせ」も可 | 内定比較で未指定の場合 |

企業名だけの「〇〇社を分析して」は `purpose: research` としてそのまま分析へ進める。入力UIを強制しない。選考対策で希望職種・選考フェーズ・応募区分が既に十分分かっている場合も、未指定の業界・企業タイプは自動推定して進めてよい。「質問なし」「おまかせで進めて」という依頼では、企業名など実行に不可欠な情報以外を聞き続けない。

## 回答の反映

- 一度に最大3問を出す。後続の項目が回答に依存するときは、その回答後に次の質問を出す。
- `arguments` 以外の内部フィールドを質問ツールに渡さない。`async` では質問と `bindings` を順番で、`standard`（`AskUserQuestion` 含む）では質問の `id` / `header` と `bindings.field` で対応づける。
- 選択結果のラベルに対応する `bindings.updates` を前の `state` にマージする。例：「ソフトウェア・AI・データ」を選んだら `role: software-ai-engineer` を設定する。画面内の位置や番号をパターンIDとして使わない。
- 自由入力は `bindings.field` へ保存する。候補外の入力・自由記述も尊重し、既存のパターンIDへ対応できない内容を無理に既定値へ変えない。必要な部分だけ短く確認する。
- 逆質問（応募者から企業への質問）の件数は `reverse_question_count`、想定質問（企業・面接官から応募者への質問）の件数は `interview_question_count` に保存する。標準はそれぞれ10問・100問。質問文でも方向と標準件数を明示し、片方の回答で両方を更新しない。
- 両方とも自由入力の「7」「7問」「７問」も受け付ける。0以上の整数以外なら、その種類の件数だけ再確認する。既に指定している件数は再質問しない。企業研究と内定比較ではこれらを聞かない（オファー面談の確認質問は別枠）。
- `standard` のグループ回答は `industry_choices` 等を更新する。次の実行で個別の候補を表示する。選択後のグループ情報は最終設定から除かれる。
- `text_questions` があれば、その内容だけをチャットで短く尋ねる。`standard` ツールが自由入力だけの質問を受け付けない場合、企業名はチャットで聞く。選択肢を架空の企業名で埋めない。
- 非同期ツールでは実際の返答が届くまで依存する分析を開始しない。未送信の初期選択、無回答、キャンセルを回答として扱わない。キャンセルされた場合はUIの再表示を繰り返さず、既存情報だけで進められる範囲を示す。

## 入力完了後

`status: ready` の `configuration` を分析条件に使う。`unresolved_axes` の `auto` はユーザーが指定を委ねた状態であり、確定したパターンIDではない。業界・企業タイプは公式情報から推定し、職種・応募区分が未定なら未定として扱う。実際の面接官・本人の経験は推定で創作しない。`auto` を `pattern_selector.py` や `report_generator.py` へ渡さない。

選択した条件を1〜2行で示して、そのまま分析を始める。追加の「この条件で開始してよいか」の確認は不要。`output_mode: research` は企業研究用テンプレートへ、`full`・`cheatsheet`・`offer-comparison` は対応する選考用テンプレートへ進む。

フル版・直前版では、`configuration.reverse_question_count` の件数で応募者から企業への逆質問を、`configuration.interview_question_count` の件数で企業側から応募者への想定質問を作る。スクリプトには `report_generator.py --reverse-question-count N --interview-question-count M` として別々に渡す。0問ならその種類のセクションだけを省略する。テンプレートの例よりユーザーの指定を優先し、各リストを別々の見出しと通し番号で出力する。

自己紹介は [会話履歴から作る約1分の自己紹介](self-introduction.md) に従って作る。毎回プロフィールの入力画面を出さず、利用可能な会話履歴・提供資料の経歴を使う。十分な情報がない場合だけ、現在の所属・代表的な経験・成果・強みを自由入力で1問にまとめて確認する。

## 対応範囲

質問UIの有無や制約は、アプリ・CLI・バージョン・実行モードに依存する。`agents/openai.yaml` は表示名や起動プロンプトを設定するもので、入力フォームの定義先ではない。独自フォームを一画面に固定表示したい場合は、別途MCPのフォーム機能またはMCP Apps UIが必要。
